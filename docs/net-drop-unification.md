# Доработка: унификация 06-net-drop и 11-dc-drop

Статус: **предложение**. Реализовать при следующем изменении сетевых тестов.

## Проблема

`06-net-drop.sh` и `11-dc-drop.sh` — по сути один и тот же тест (блокировка
YDB-портов через iptables REJECT/DROP), отличаются только радиусом:

| | 06-net-drop | 11-dc-drop |
|---|---|---|
| `TEST_SCOPE` | `single` | `dc` |
| teardown | `nemesis_iptables_teardown` на `NODE_HOST` | `nemesis_iptables_teardown_all "${DC_HOSTS[@]}"` |
| check | один `CHECK_HOST` | цикл по `DC_HOSTS[@]` |
| остальное | идентично | идентично |

Это тот же паттерн «один немезис — узел и ДЦ», что и у tc-тестов
(04/05/07 обслуживаются одним `tc` с флагами `-1`/`-4`). Два отдельных файла
для net-drop — историческая случайность, а не осознанное решение. Дублирование
уже привело к расхождению: в 06 при teardown зовётся `nemesis_iptables_teardown`
(один хост), в 11 — `nemesis_iptables_teardown_all` (массив). Любая правка
немезиса требует синхронного редактирования обоих.

## Предлагаемое решение

Слить в один параметризованный тест по образцу tc-семейства: **радиус задаётся
стандартным флагом CLI** (`-1` узел / `-4` ДЦ / `-A` альт-ДЦ), а не выбором
файла.

1. **`06-net-drop.sh` — единственный источник логики.** Убрать жёсткий
   `TEST_SCOPE="single"`; scope определяется переданным флагом
   (`chaos_require_scope` уже это умеет для tc-тестов). Ветки check/teardown
   сделать scope-агностичными: брать список хостов из уже разрешённых целей
   (`chaos_resolve_targets` → `TARGET_HOSTS[@]` или аналог), а не из
   `NODE_HOST`/`DC_HOSTS` по отдельности. Тогда один и тот же код обслуживает
   и узел, и ДЦ — как это делает `tc`.

2. **`11-dc-drop.sh` — тонкая синтаксическая обёртка** над 06, ради обратной
   совместимости и читаемости в списке тестов:
   ```bash
   #!/usr/bin/env bash
   # 11 — псевдоним 06-net-drop с радиусом «весь ДЦ». См. 06-net-drop.sh.
   set -euo pipefail
   SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
   # если пользователь не задал радиус — по умолчанию весь ДЦ (-4)
   exec "${SCRIPT_DIR}/06-net-drop.sh" "${@:- -4}"
   ```
   (точную подстановку дефолтного `-4` согласовать с тем, как
   `chaos_parse_common` разбирает аргументы; при необходимости — явный
   `--scope dc`).

3. **Параметры 06 привести к общему виду** остальных тестов: те же
   `-1/-4/-A/-t/-D/-C/-N`, тот же `--drop`, та же логика teardown-таймера на
   хосте. Никаких особых кейсов для ДЦ, кроме перебора списка хостов.

## Проверки после реализации

- `06-net-drop.sh -1` и `-4` дают тот же эффект, что старые 06/11.
- `-C` (check) и `-D` (teardown) корректно работают в обоих радиусах.
- Аннотации Grafana (`scope=node` / `scope=dc`) проставляются по фактическому
  радиусу, а не по имени файла.
- `11-dc-drop.sh` без аргументов эквивалентен `06-net-drop.sh -4`.
