# Методика нагрузочных и хаос-экспериментов

## Подготовка

Используй отдельный каталог таблиц и один работающий генератор. До измерения заверши импорт и создание индексов. Проверь права на таблицы и индексы, свободное место, состояние базы и сбор метрик с базы и генератора. Не выполняй импорт одновременно с измерением.

Сохрани конфигурацию и результаты в `out/`. Зафиксируй версию генератора, склады, потоки, `inflight`, режим транзакций, прогрев, длительность измерения, штатные паузы и смесь транзакций. Настройки конкретного окружения должны оставаться локальными.

Штатные паузы включаются через `TPCC_NO_DELAYS=false`. Режим без пауз создаёт инженерную нагрузку насыщения. Такой прогон нельзя выдавать за стандартный TPC-C. Даже со штатными паузами короткий внутренний эксперимент не становится официальным результатом TPC-C.

При подборе меняй один параметр за раз. Число складов задаёт размер данных и количество моделируемых терминалов. `inflight` ограничивает одновременно выполняемые транзакции. Потоки задают число рабочих потоков генератора. Оценка около 50 inflight на ядро служит ориентиром для генератора, но не является требованием стандарта и не заменяет измерения загрузки.

## Измерение

```bash
TPCC_WARMUP_MIN=5 bash tpcc.sh run 3000 5 256 20
bash evaluate-run.sh ../out/workload-portable-tpcc/logs/ИМЯ_ЖУРНАЛА.log
```

В этом проекте критерий требует efficiency строго выше 90% и p90 строго ниже 5000 мс для всех пяти типов транзакций. Скрипт `evaluate-run.sh` читает итоговый блок, сообщает `PASS` или `FAIL` и отклоняет неполные результаты. Проверь также фактическую длительность: итог прерванного прогона не подтверждает прохождение запланированного теста. Этот внутренний критерий не доказывает соблюдение всех требований стандарта TPC-C.

Для серии по `inflight` передай значения в `staircase.sh`:

```bash
TPCC_WAREHOUSES=3000 TPCC_THREADS=5 TPCC_DURATION_MIN=5 \
  TPCC_WARMUP_MIN=2 bash staircase.sh 150 180 210 240
```

Каждая ступень запускает отдельный прогрев и измерение. Скрипт сохраняет журналы и `manifest.tsv`. При заданных `TPCC_GRAFANA_URL` и `TPCC_GRAFANA_TOKEN` скрипт размечает общий интервал серии и отдельные ступени. На дашборде должен быть включён запрос аннотаций с тегом `tpcc-step`.

## Калибровка хаосов

Запусти длительную нагрузку с выбранными параметрами. Проверь стабильный исходный уровень. Затем подбери параметры воздействия на узел и группу узлов. `calibrate-chaos.sh` поддерживает процессор, задержку, потери и полосу сети:

```bash
bash calibrate-chaos.sh cpu node 90
bash calibrate-chaos.sh delay node 5
bash calibrate-chaos.sh loss dc 2
bash calibrate-chaos.sh bandwidth dc 500
```

Примеры задают начальные кандидаты, а не универсальные пороги. Скрипт измеряет исходную фазу, воздействие и восстановление. Длительности задают `TPCC_BASELINE_SEC`, `TPCC_IMPACT_SEC` и `TPCC_RECOVERY_SEC`. Каждая фаза должна длиться не менее 60 секунд. Результаты сохраняются в `out/workload-portable-tpcc/calibration/`.

Сравнивай скорость успешных транзакций, ошибки и восстановление. Накопленный p90 за окно не показывает отдельный перцентиль воздействия. Режим `TPCC_CALIBRATION_P90_MODE=phase` отключает исходную проверку накопленного p90 перед воздействием. Режим не пересчитывает перцентиль отдельной фазы. В отчёте обозначай такие значения как среднее накопленного p90 за окно.

## Комплект экспериментов

Задай откалиброванные значения `SUITE_CPU_NODE`, `SUITE_CPU_DC`, `SUITE_DELAY_NODE`, `SUITE_DELAY_DC`, `SUITE_LOSS_NODE`, `SUITE_LOSS_DC`, `SUITE_BW_NODE`, `SUITE_BW_DC`. Укажи выделенный диск данных через `SUITE_DISK_DEVICE`. Конфигурация `env.sh` должна определять цели и порты YDB. Перед запуском проверь план:

```bash
bash run-chaos-suite.sh --plan
bash run-chaos-suite.sh
```

Комплект исключает воздействие на оперативную память и последовательное обновление. Скрипт сохраняет журналы и `results.tsv` с фазами, скоростью, ошибками и задержками. Аннотации хаосов привязываются к дашборду `portable-tpcc-chaos`.

Перед следующим воздействием проверь восстановление базы и исходной скорости. Если восстановление не завершилось, предыдущую фазу нельзя использовать как исходный уровень следующего эксперимента. В отчёте укажи дату, время и часовой пояс каждого теста, параметры нагрузки и воздействия, метод расчёта показателей и ограничения измерений.
